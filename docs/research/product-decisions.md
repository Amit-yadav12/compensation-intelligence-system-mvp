# Product Decisions — Observation → Decision → Reason

Each research observation maps to an explicit product or architecture decision.

| # | Observation (from competitor analysis) | Decision | Reason |
|---|----------------------------------------|----------|--------|
| 1 | Levels.fyi's level-first model is its main advantage; AmbitionBox/Glassdoor mixing seniorities into one title number is misleading | **Canonical levels are first-class domain entities.** Every compensation record carries both a company-specific level and a canonical level. Comparison, benchmarking and company analytics group by canonical level. | "Levels matter more than job titles" is the product thesis. A title-only aggregate is statistically noisy. |
| 2 | Company levels (Google L4, Microsoft 62, Amazon SDE II) are not literally identical | **CompanyLevel and CanonicalLevel are separate tables with an explicit mapping; the UI labels mappings as approximate.** | Honesty: mapping is a configured heuristic, not a claim of equivalence. The schema lets mappings be refined later. |
| 3 | All four products have hidden company-name hygiene problems ("Google India Pvt. Ltd." vs "Google") | **Company normalization pipeline: trim → lowercase → punctuation → whitespace → legal-suffix removal → CompanyAlias lookup → canonical Company.** Never trust raw company text as identity. | Deterministic, testable resolution; aliases are data, not code; canonical identity is the join key for all analytics. |
| 4 | Location variants (Bangalore/Bengaluru, Bombay/Mumbai, Gurgaon/Delhi NCR, NYC/New York) fragment aggregates | **Location normalization with an explicit alias map; city/state/county stored separately; currency attached to location.** | Same reasons as companies: deterministic resolution, clean joins, correct currency handling. |
| 5 | Percentile/range framing (6figr, Glassdoor) feels more trustworthy than point estimates | **Benchmark engine always returns min, P25, median, P75, P90, max, sample size.** One well-tested quantile module; no scattered stats code. | Ranges communicate variance; a single mean hides bimodal or skewed distributions. |
| 6 | Tiny cohorts are presented with false precision everywhere | **Coverage label: n<10 Low, 10–49 Moderate, 50+ Strong. n is always shown. Wording changes with coverage.** | Transparent confidence signal without claiming formal statistical confidence. |
| 7 | Levels.fyi's base/stock/bonus split is core to its usefulness | **Compensation records always split base, bonus, stock; TC is derived. Mix engine computes baseRatio/stockRatio/bonusRatio.** | Structure enables comparison of package *shape*, not just size. |
| 8 | Client-side filtering of thousands of rows is slow and breaks URL sharing | **All filtering, sorting, pagination run server-side in PostgreSQL via Drizzle; state lives in URL query params.** | Performance, shareability, back/forward support, testability, and it prevents the "fetch everything" anti-pattern. |
| 9 | AmbitionBox/Glassdoor paywalls damage trust in the core loop | **All intelligence (explore, company, compare, benchmark) is free; only submission requires auth.** | Maximizes the value demonstration loop; auth is required only where identity matters (attribution + dedupe). |
| 10 | Opaque ML salary estimates (Glassdoor "estimated") are unverifiable | **Deterministic analytics first. AI feature (optional) only summarizes a structured factual payload produced by the analytics engine — never invents numbers.** | Data integrity > novelty. Every number is traceable to SQL. |
| 11 | Contribution spam/duplication degrades crowdsourced datasets | **Deterministic dedupeKey (company+role+level+location+components+experience+month) with a DB unique constraint; 23505 → DUPLICATE_COMPENSATION.** | Application checks race; only the database constraint is race-safe. |
| 12 | Clients can tamper with totals (post a base of 100k with TC 10M) | **Server recomputes totalCompensation = base + bonus + stock; client-supplied total is ignored.** | Single invariant enforced in one place (domain service). |
| 13 | Missing bonus/stock is common and NaN-poisoning analytics | **Missing bonus/stock normalize to 0 in domain logic; non-negative constraints enforced by Zod and DB checks.** | Avoids null-propagation bugs; negative money is semantically invalid for this MVP. |
| 14 | Competitor APIs are inconsistent, ad-hoc | **Consistent error model: `{ error: { code, message } }` with a fixed code enum (VALIDATION_ERROR, COMPANY_NOT_FOUND, DUPLICATE_COMPENSATION, …).** | Predictable client handling, stable error codes for debugging, no stack traces in production. |
| 15 | Salary sites need rich company pages | **/companies/[slug] renders snapshot, level table with percentiles, mix, locations, roles, freshness, and coverage — all from grouped/aggregate queries.** | Company page is the second most important surface; aggregates must be cheap (no full-table scans, no N+1). |
| 16 | Users want "how does this company compare" | **/compare is cohort-scoped (role family + role + canonical level + location + experience band). 2–3 companies.** | Comparing a Google L5 in Bengaluru with an Amazon SDE II in Seattle is meaningless; cohort scoping prevents invalid comparisons. |
| 17 | Location differentials are interesting only within comparable cohorts | **Location differential is computed only within a matched cohort (same role/level), never across cohorts.** | Prevents misleading claims ("Bengaluru pays 40% less" while comparing different levels). |
| 18 | The demo dataset is synthetic | **Every surface carries a synthetic-data notice; verificationStatus is `unverified`; sourceType `self_reported`; README states it explicitly.** | Data honesty is a hard requirement; the system demonstrates architecture, not verified market truth. |
| 19 | Evaluators need to understand architecture decisions | **ADRs + interview-notes.md capturing the "why" for every major choice (Postgres, Drizzle, modular monolith, server-side TC, aliases, canonical levels, deterministic analytics).** | Explainability is part of the submission's evaluation criteria. |
| 20 | Assignment requests Prisma; environment provides Drizzle | **Use Drizzle ORM (provisioned by the environment) with the same schema concepts: migration-first, typed relational models, explicit indexes.** | Equivalent relational modeling; both give type-safe SQL + migrations. Documented as a substitution in ADR-002. |
